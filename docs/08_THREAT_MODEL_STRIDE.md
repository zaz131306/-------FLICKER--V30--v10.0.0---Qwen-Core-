## 0. Границы системы и модель нарушителя

### 0.1. Что внутри границы доверия

| Компонент | Доверенный? | Обоснование |
|---|---|---|
| `symbolic-core` (Rust) | **да** | 0 зависимостей, 0 unsafe, код аудируем целиком (6 068 строк) |
| `flicker-supervisor` (Том 1) | **да** | привилегированный, но не содержит бизнес-логики |
| `flicker-worker` (Том 2) | **частично** | доверенный код, но обрабатывает недоверенные данные |
| **Выход LLM (Qwen3.5)** | **НЕТ** | главный источник недоверенных данных |
| **Данные из базы знаний** | **НЕТ** | внешние источники, возможен враждебный контент |
| **Запрос оператора** | **НЕТ** | свободный текст, возможен prompt injection |
| **PDDL-домен** | **частично** | пишется человеком или моделью; проверяется парсером |

### 0.2. Ключевой принцип

**Недоверенным считается всё, что порождено моделью или пришло извне, включая синтаксически валидный PDDL** (R9.5). Доверие возникает не из источника данных, а из прохождения барьеров B1–B9.

### 0.3. Что система НЕ защищает

Честная граница ответственности. Следующее **не устраняется** архитектурой:

1. **E4 — неполнота доменной модели.** Измерено red-team suite: **rate = 1.0000**. Если в мире есть ограничение, которого нет в PDDL, система выдаст формально валидный план, его нарушающий. См. `docs/07` §6.1.
2. **E3 — ошибка трансляции ЕЯ→PDDL в части намерения.** Валидатор проверяет соответствие плана модели, а не модели — намерению. Митигация: R7.5.5 (цель предъявляется оператору) — организационная, не конструктивная.
3. **Компрометация хоста.** При полном контроле хоста злоумышленник читает память, подменяет бинарники и журнал. Митигация — TEE/secure boot (DEP-HW-01), не реализована.
4. **Инсайдер с правами оператора.** Оператор, подтверждающий план, является доверенным лицом; система не оценивает его мотивацию.
5. **Сговор оператора и администратора.** Разделение ролей не защищает от сговора.

## 5. Что проверено эмпирически

| Проверка | Результат | Где |
|---|---|---|
| Сеть из песочницы заблокирована | `NET_BLOCKED PermissionError errno=1` | `verify_isolation()` |
| Корень только для чтения | `root_readonly=True` | то же |
| `/tmp` доступен для записи | `tmp_writable=True` | то же |
| Окружение не наследуется | `env_not_leaked=True` (0 совпадений) | то же |
| Таймаут прерывает зависание | `timeout_elapsed_ms=2004` при лимите 2000 | то же |
| RLIMIT_AS срабатывает | `ALLOC_BLOCKED` | то же |
| seccomp запрещает `socket()` | `SOCKET_EPERM 1` | то же |
| seccomp запрещает `ptrace` | `PTRACE -1 1` | то же |
| seccomp selftest | `SELFTEST OK` | `flicker_seccomp --selftest` |
| Crypto-erase с верификацией | `master_destroyed`, `verification_passed`, 3/3 производных, 0 мс | `flicker-supervisor selftest` |
| Anti-replay | повтор и откат `sequence` отклоняются | то же |
| AAD привязывает session_id и sequence | MAC различается | то же |
| Подлог replay-цепи (6 видов мутаций) | обнаруживается, оба языка | `test_interop.py`, `guarantees_a2_a3_a4.rs` |
| Подмена provenance задним числом | обнаруживается пересчётом `row_hash` | `test_b3_iep.py` |
| Обход фильтра свежести через SQL-приоритет | **найден и исправлен**, регрессионный тест | `test_neighbors_age_filter_applies_to_both_directions` |

### 5.1. Ограничение проверки

Проверки IEP (§5, строки 1–9) **выполнены в ходе разработки** и дали все значения `True`. При повторном прогоне в той же песочнице bwrap стал недоступен: `Creating new namespace failed: nesting depth or /proc/sys/user/max_*_namespaces exceeded (ENOSPC)` — исчерпание лимита окружения после серии запусков, не дефект кода.

Тесты при этом **не отражаются как пройденные**: они переходят в состояние `SKIP` с явным перечнем непроверенного (требование 4.8). Итог прогона выводится как `15 passed · 8 skipped · 0 failed`. В CI на хосте с доступными user namespaces эти 8 проверок обязательны к исполнению.
