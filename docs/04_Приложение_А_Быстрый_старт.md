## 4. Проверка криптографии и тестового покрытия

**СТАТУС ОБНОВЛЁН Отчётом №1 (эррата Э-1).**

`symbolic-core` содержит собственную реализацию SHA-256 и HMAC-SHA-256, на которых
держится вся replay-цепочка (гарантия **G4**). Ранее этот пункт значился как
«приоритет №1, тест-векторов нет». **Проверка показала обратное:**

```bash
cargo test -p symbolic-core sha2 -- --nocapture
```

В `sha2.rs` **7 тестов**, векторы сверены и корректны:

| Тест | Вход | Хэш | Источник |
|---|---|---|---|
| `kat_empty` | `""` | `e3b0c442…b7852b855` | FIPS 180-4 ✅ |
| `kat_abc` | `"abc"` | `ba7816bf…f20015ad` | FIPS 180-4 ✅ |
| `kat_long` | 10⁶ × `'a'` | `cdc76e5c…ccc7112cd0` | FIPS 180-4 ✅ |
| `kat_multiblock_incremental` | `"abcdbcde…nopnopq"` | `248d6a61…19db06c1` | FIPS 180-4 ✅ |
| `incremental_equals_oneshot` | 1000 Б, чанки по 7 | = one-shot | ✅ |
| `hmac_rfc4231_case1` | key=20×`0x0b`, `"Hi There"` | `b0344c61…26e9376c2e32cff7` | RFC 4231 ✅ |

Требование R14.1.1 для SHA-256/HMAC **выполнено**. Не проверено: векторы RFC 8259 для `json.rs`.

### 4.1. Настоящий приоритет №1 — покрытие нормативной семантики

```bash
# ОЖИДАНИЕ НА 09.10.2026: ноль тестов в каждом из этих модулей
cargo test -p symbolic-core pddl     # pddl.rs,   986 строк — 0 тестов
cargo test -p symbolic-core planner  # planner.rs, 305 строк — 0 тестов
cargo test -p symbolic-core mcts     # mcts.rs,    240 строк — 0 тестов
cargo test --workspace               # каталога tests/ нет — интеграционных тестов нет
```

1 638 строк (41 % кодовой базы) без единого теста. Сквозной конвейер
`parse_domain → build_model → ground_actions → plan → validate_plan → replay`
(то есть реализация G1–G4) **ни разу не проверен как целое**.

`validator.rs` имеет 5 тестов, но проверяет планы против `Model`, построенной
**нетестированным** `pddl.rs`: дефект парсера обесценивает валидацию целиком.

**Рекомендация Р-01 (Отчёт №1), 6–8 нед, блокирует все остальные работы.**

### 4.2. Проверка детерминизма коллекций (R8.1.1, исправлено)

Запрещена **итерация** по `HashMap`/`HashSet`, а не их использование:

```bash
# ищем ИТЕРАЦИИ, а не объявления. Lookup-only использования допустимы.
grep -rnE '\b(HashMap|HashSet)\b' crates/symbolic-core/src/     # 4 совпадения
grep -rnE '(states|parent|closed)\.(iter|keys|values)\(' crates/symbolic-core/src/
# ОЖИДАНИЕ: 0 совпадений -> G3 не нарушен
```

В `planner::best_first` все 4 использования (`states`, `parent`, `closed`) —
lookup-only (`insert`/`get`/`contains_key`/`contains`). Порядок обхода задаётся
`BinaryHeap<HeapItem{h, depth, seq}>` с монотонным `seq` (полный детерминированный
порядок при равных `h` и `depth`) и предварительно отсортированным `ground`.

## 5. Клиент планирования (ЦЕЛЕВОЕ, не реализовано)

```bash
# проверка домена и задачи на соответствие FPS-1
flicker-plan check   --domain logistics.pddl --problem p1.pddl

# планирование, профиль auto
flicker-plan plan    --domain logistics.pddl --problem p1.pddl \
                     --mode auto --seed 42 --budget-ms 5000

# явный режим
flicker-plan plan    --mode mcts --mcts-iterations 20000 ...
flicker-plan plan    --mode best-first --max-nodes 200000 ...

# независимая валидация уже выданного плана (R7.4.4)
flicker-plan validate --domain ... --problem ... --plan plan.json

# верификация replay-цепочки
flicker-plan replay-verify --chain trace.jsonl

# детерминированный повтор
flicker-plan replay --chain trace.jsonl --assert-identical
```

Соответствие API в `symbolic-core`:

| CLI | Вызов |
|---|---|
| `check` | `pddl::check_domain`, `pddl::parse_problem` |
| `plan` | `pddl::load` → `ground::ground_actions_with_cap` → `planner::plan` |
| `validate` | `validator::validate_plan` |
| `replay-verify` | `replay::verify_chain` |

`--mode` маппится в `PlanMode::parse` (`auto` / `best-first`/`bestfirst`/`bf` / `mcts`).

## 7. Запуск модельного слоя (Qwen3.5, профиль P0)

```bash
# веса скачиваются ОТДЕЛЬНО и хешируются (R5.2.3, model_pin.yaml)
sha256sum ./models/Qwen3.5-27B/*.safetensors

# хэш по ОТСОРТИРОВАННОМУ списку шардов — иначе порядок обхода ФС
# даст ложные несовпадения model_pin
find ./models/Qwen3.5-27B -name '*.safetensors' -print0 \
  | sort -z | xargs -0 sha256sum | sha256sum

python -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen3.5-27B \
  --quantization awq \
  --tensor-parallel-size 1 \
  --max-model-len 16384 \
  --temperature 0.0 --top-p 0.0 --top-k 1 --seed 42 \
  --guided-decoding-backend xgrammar \
  --no-enable-speculative-decoding \
  --trust-remote-code=false
```

**Запрещено** (§5.3): speculative decoding, `temperature > 0`, `top_p > 0`,
`trust_remote_code: true`. Каждое из них ломает G3 или открывает RCE.
